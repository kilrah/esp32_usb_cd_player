# Guition JC1060P470-V2 (ESP32-P4): hardware notes

The board's own documentation is scarce and mostly in schematic or image form. This page collects in text
what is known about it: chips, pins, connectors and the settings that work.

**Version:** the JC1060P470 exists in three versions. This page and the firmware are for the **-V2**. On the
other versions the display doesn't work with this firmware.

## Sources

Every fact below is marked with where it comes from:

| Mark | Source |
|---|---|
| **V** | Verified on the V2 board by this project (it runs this way in [components/jc1060p470_v2](../components/jc1060p470_v2)) |
| **C** | Code that works on the board: the vendor demo, or the `p4_edge_enhancer` project (camera) on the same board |
| **S** | The vendor schematic `JC1060P470C_I_W_Y-V1.0.pdf` (title block: `JC1060P470C_I_Y_V0.2`, 9/06/2025), kept in the `p4_edge_enhancer` repo. It may describe an earlier revision than the V2: see [Differences](#differences-between-the-schematic-and-the-v2) |

| Part | Chip | Notes |
|---|---|---|

## I2C bus (GPIO7 SDA, GPIO8 SCL)

| Address (7-bit) | Device | Mark |
|---|---|---|
| 0x18 | ES8311 codec (CE pin pulled low) | **V** |
| 0x32 | RX8025T real-time clock (fixed address of the chip) | **S** |
| 0x36 | OV02C10 camera (SCCB) | **C** |
| 0x5D | GT911 touch (the driver's default) | **V** |

The camera connector has 2.2 kΩ pull-ups on the bus. Further devices can go on CN3.

## Display

| Item | Value | Mark |
|---|---|---|
| Connector | FPC1, 30 pins, 0.5 mm, bottom contact | **S** |
| Interface | MIPI-DSI, 2 data lanes, 750 Mbit/s per lane (`JD9165_PANEL_BUS_DSI_2CH_CONFIG()`) | **V** |
| Pixel clock | 52 MHz, RGB565 | **V** |
| Timing | H: 1024 visible, back porch 136, sync 24, front porch 160. V: 600 visible, back porch 21, sync 2, front porch 12 | **V** |
| MIPI PHY supply | P4 internal LDO channel 3 at 2.5 V (`esp_ldo_acquire_channel()`); also used by the CSI PHY | **V** |
| Init sequence | Vendor sequence in [jc1060p470_v2.c](../components/jc1060p470_v2/jc1060p470_v2.c) (from the vendor demo) | **V** |
| Panel straps | `UPDN` and `STBYB` pulled up, `SHLR` pulled down (scan direction, standby) | **S** |
| Panel supplies | `LCD_DC-DC` block generates the panel's VGH, VGL, AVDD and VCOM | **S** |
| Backlight | MP3202 boost (from the battery / 5 V rail) to `LEDA`/`LEDK`; GPIO23 drives its EN pin as PWM. This firmware: LEDC 5 kHz, 10-bit | **V** |

`swap_xy` isn't supported by the JD9165 driver (logged as an error at boot, harmless).

The DPI panel's DMA is restarted from the DSI interrupt every frame, so that ISR must stay in IRAM
(`CONFIG_LCD_DSI_ISR_CACHE_SAFE`) and the flush callback with it. Without this the screen flashes during flash
writes (OTA, LittleFS).

| Item | Value | Mark |
|---|---|---|

## Camera

| Item | Value | Mark |
|---|---|---|
| Sensor | OmniVision **OV02C10**, 2 MP (1920x1080), RAW10 | **C** |
| Connector | FPC2, 15 pins, 0.3 mm, flip-lock, bottom contact | **S** |
| Interface | MIPI-CSI, connector wired for 2 data lanes (`CSI_A_DATA0/1`, `CSI_A_CLK`) | **S** |
| Modes used | 1288x728 RAW10 30 fps (default), 1920x1080 RAW10 30 fps on **1 lane** | **C** |
| Control | SCCB on the shared I2C bus (GPIO8 SCL, GPIO7 SDA), address 0x36, 100 kHz | **C** |
| Reset / power-down | Not connected to GPIOs: the connector's `CSI_IO0` has a 10 kΩ pull-up, `CSI_IO1` isn't routed. Drivers get -1 for both | **S**, **C** |
| Supply | 3.3 V (`ESP_3V3`) on the connector | **S** |

The OV02C10 driver isn't in the upstream `esp_cam_sensor` (2.1.0): the vendor added it. `p4_edge_enhancer`
keeps local, modified copies of `esp_cam_sensor` and `esp_video` for it (flip settings, register tables, ISP
pipeline changes), and an IPA tuning file `ov02c10_default_p4_eco4.json`. Settings used there:
`CONFIG_CAMERA_OV02C10=y`, `CONFIG_CAMERA_OV02C10_MIPI_RAW10_1920x1080_30FPS=y`,
`CONFIG_ESP_VIDEO_ENABLE_ISP_PIPELINE_CONTROLLER=y`. It was measured with the P4 at 360 MHz.

## Ethernet

| Item | Value | Mark |
|---|---|---|
| PHY | IP101GR, PHY address 1 (straps: `PHY_AD0` pulled up, `PHY_AD3` pulled down), 25 MHz crystal | **V** (address, ID), **S** (straps, crystal) |
| Interface | RMII; the PHY outputs the 50 MHz reference clock to GPIO50 | **V** |
| Driver | ESP-IDF's generic 802.3 PHY driver works (`esp_eth_phy_new_generic()`); 100 Mbps full duplex | **V** |
| Connector | RJ45 with discrete magnetics and two LEDs (driven by `PHY_AD0` / `PHY_AD3`) | **S** |

## USB

| Port | Function | Mark |
|---|---|---|
| USB-C "USB1" (full speed) | USB-Serial-JTAG: console and cable flashing (COM13 on the PC used here) | **V** |
| USB-C (high speed) | USB 2.0 OTG high speed (480 Mbit/s), used as USB host here | **V** |

Both ports have 5.1 kΩ pull-downs on CC (they ask a charger / PC for 5 V) and ESD diodes. **S**: their VBUS
pins are both tied to the 5 V input rail `USB5V_IN`, which also comes from connector CN2. There is no switch:
a device on the high-speed port gets the board's 5 V input directly. The battery booster's output (`VOUT-BAT`)
isn't connected to that rail in the schematic, so on battery power alone the host port may have no VBUS (not
checked on the V2).

## Power

| Item | Value | Mark |
|---|---|---|

| Battery | CN4; IP5306 charges it from `USB5V_IN` and boosts it to 5 V (`VOUT-BAT`), which supplies the 3.3 V buck, the backlight and the expansion header | **S** |
| Battery button | SW3 on the IP5306's KEY input (power on/off) | **S** |
| 3.3 V | TLV62569 buck from `VOUT-BAT` (`ESP_3V3`, `VCC3V3`) | **S** |
| Battery sense | GPIO53 (see the GPIO map) | **S** |

## Buttons

| Button | Function | Mark |
|---|---|---|
| SW1 | BOOT (GPIO35 low): hold while pressing RST for download mode | **S** |
| SW2 | RST (`CHIP_PU`) | **S** |
| SW3 | IP5306 KEY: battery power on/off | **S** |

## Connectors

### JP1: expansion header (2x13)

| Pin | Signal | Pin | Signal |
|---|---|---|---|
| 1 | 3.3 V | 2 | `VOUT-BAT` (5 V) |
| 3 | 3.3 V | 4 | `VOUT-BAT` (5 V) |
| 5 | GND | 6 | GND |
| 7 | GPIO1 | 8 | not connected |
| 9 | GPIO2 | 10 | GPIO47 |
| 11 | GPIO3 | 12 | GPIO46 |
| 13 | GPIO4 | 14 | GPIO45 |
| 15 | GPIO5 | 16 | GND |
| 17 | GPIO20 | 18 | 3.3 V |
| 19 | GPIO32 | 20 | C6 UART0 RX |
| 21 | GPIO33 | 22 | C6 UART0 TX |
| 23 | I2C SDA (GPIO7) | 24 | C6 IO9 (C6 boot strap) |
| 25 | I2C SCL (GPIO8) | 26 | C6 `CHIP_PU` (C6 reset) |

Pins 3-13 of the odd row (3.3 V, GND, GPIO1-4) take a PCM5102 module plugged straight on: VCC, GND, LRCK,
DIN, BCK, SCK. Pins 20-26 allow flashing the C6 (its UART0, IO9 and reset).

| Connector | Pins | Signals | Mark |

| CN3 (MX1.25, 4 pins) | 1 GND, 2 3.3 V, 3 SCL, 4 SDA | I2C (shared bus) | **S** |

| J5 (4 pins) | 1 `USB5V_IN`, 2 TX1 (GPIO26), 3 RX1 (GPIO27), 4 GND | UART1 at logic level (the same lines as the MAX485) | **S** |
| J1 | microSD slot (see GPIO39-44) | | **S** |
| RJ1 | RJ45 Ethernet | | **S** |
| FPC1 / FPC2 / FPC3 | Display / camera / touch | See their sections | **S** |

**RS-485 direction:** the MAX485's DE/RE (net `EN`) is driven from TX1 through a 74LVC1G132 Schmitt NAND and
an 8550 transistor with an RC hold time: the driver turns on while transmitting, without a direction GPIO.

## Differences between the schematic and the V2

- **LCD reset:** the schematic routes `LCD_RST` to GPIO0 (FPC1 pin 4). The vendor demo and this firmware use
  GPIO5 on the V2, and the display works. Treat GPIO0 / GPIO5 as unconfirmed until checked on the board.
- **Revision:** the schematic's title block says `JC1060P470C_I_Y_V0.2`, the file name `V1.0`. The pins
  verified on the V2 (Ethernet, I2C, I2S, amplifier, backlight, C6 SDIO and reset) all match it.
- **Host-port VBUS on battery:** see [USB](#usb). Not checked on the V2.
